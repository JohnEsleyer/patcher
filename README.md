
# 🩹 patcher

A lightweight CLI tool designed to apply multi-file changes and code modifications from AI assistant outputs directly to your project.

---

## 🌟 Overview

When copying code suggestions from AI models, manually opening multiple files and navigating to the right lines is tedious and error-prone. 

`patcher` automates this process: you copy the assistant's output into a text file and run `patcher <file.txt>`. Any conversational text, markdown formatting, or notes outside the XML tags are automatically ignored.

### 🛡️ Safety & Reliability Guarantees
- **Atomic Two-Pass Validation:** Validates the entire patch in an in-memory virtual filesystem before modifying disk. If any search target or tag is invalid, **no files are touched**.
- **Anti-Corruption Tag Shield:** Detects unclosed tags and nested directives immediately, preventing `<file>` blocks from accidentally swallowing subsequent `<replace>` tags.
- **Ordered Sequential Execution:** Operations run strictly in document order, supporting sequential edits to the same file.
- **Fuzzy Search Tolerance:** Automatically handles CRLF/LF line endings, trailing whitespace differences, and tab-vs-space indentation variations.
- **Code Fence Stripping:** Automatically removes accidental outer ` ```lang ` wrappers generated by assistants inside `<file>` blocks.

## 🚀 Installation

### 1. Build
Inside the directory containing `main.go`:

```bash
go build -o patcher main.go
```

### 2. Move to PATH
Move the binary to any directory in your system `$PATH`:

```bash
# User-local (recommended)
mv patcher ~/.local/bin/

# Or system-wide
sudo mv patcher /usr/local/bin/
```

Verify that it is accessible:
```bash
patcher --help
```

## 📋 The Expected Format

`patcher` looks for three XML-like tags. You can have multiple tags in a single patch file in any order.

### 1. Create or Overwrite an Entire File: `<file>`

Use this when creating a new file or completely replacing an existing one. Any missing parent directories will be created automatically.

```xml
<file path="path/to/file.ext">
... entire content of the file ...
</file>
```

#### Example:
```xml
<file path="pkg/compiler/example.go">
package compiler

func Hello() string {
    return "Hello, Ube!"
}
</file>
```

---

### 2. Search & Replace inside an Existing File: `<replace>`

Use this for targeted edits inside existing files. It requires two sub-tags:
* `<search>`: The exact block of code to find.
* `<with>`: The replacement code.

```xml
<replace path="path/to/file.ext">
<search>
    exact code block to find
</search>
<with>
    new code block to insert
</with>
</replace>
```

#### Rules for `<search>`:
- Must match the target file character-for-character, including indentation (tabs/spaces) and line breaks.
- If multiple identical blocks exist, only the first occurrence is replaced.
- Leading newlines right after the `<search>` and `<with>` opening tags are trimmed automatically for clean formatting.

#### Example:
```xml
<replace path="pkg/compiler/token.go">
<search>
	TokenDefer    TokenType = "defer"
	TokenUnsafe   TokenType = "unsafe"

	// Symbols & Operators
</search>
<with>
	TokenDefer    TokenType = "defer"
	TokenUnsafe   TokenType = "unsafe"
	TokenTrait    TokenType = "trait"

	// Symbols & Operators
</with>
</replace>
```

---

### 3. Delete a File: `<delete />`

Use this self-closing tag to delete a file if it exists.

```xml
<delete path="path/to/file.ext" />
```

#### Example:
```xml
<delete path="tests/old_test.ube" />
```

1. **Ask the assistant** for changes formatted for `patcher`.
2. **Copy the response** and paste it into a file (e.g. `patch.txt`):
   ```bash

```bash

patcher patch.txt

## 🛡️ Robustness & Formatting Features

- **Pasted Text Immunity:** Any text before, between, or after the tags is ignored.
- **Smart Quote Normalization:** Automatically converts curly/smart quotes (`“`, `”`, `‘`, `’`) introduced by some text editors into standard ASCII quotes.
- **HTML Entity Decoding:** Automatically decodes `&lt;` and `&gt;` if code was copied from rich-text browser views.
- **Line Ending Tolerance:** Normalizes `\r\n` (Windows CRLF) and `\n` (Unix LF) automatically.
